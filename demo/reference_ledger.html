Bug Report

Symptom: POST /payment retry-induced duplicate payment bug.

Competing Hypotheses

IDClaimCausal MechanismExperimentStatus
H1 The duplicate is caused by frontend/client retry behavior. Client retries POST /payment with the same payment_id after a timeout. The service processes both requests independently. disable_frontend_retry FALSIFIED
H2 The duplicate is caused by service-layer retry behavior with no idempotency check. The service's retry loop (SERVICE_RETRY_ON_TIMEOUT) executes all configured attempts even after a successful charge, without checking if payment_id was already processed. inject_backend_timeout SUPPORTED

Root Cause Conclusion

H2 CONFIRMED: The service-layer retry loop in process_payment() executes all configured retry attempts even after a successful charge, without checking for an existing transaction for the same payment_id. This is the root cause of duplicate payments. Client-side retry (H1) was experimentally excluded.

Applied Patch

Idempotency fix: (1) Check for existing transaction with same payment_id before charging. (2) Per-payment_id asyncio.Lock prevents TOCTOU race in concurrent requests. (3) Return after first successful charge — do not continue retry loop.
